## Decisions

1. **evidence names who delivered and when, not which file holds it.**
   - Top-level `agent` is the Agent whose task record scoped the deliver (the `deliveredIn` Agent) when there is one, otherwise the record's own agent. `record.kind` adds `agent-deliver` next to `manual-deliver` and `lifecycle`, and `record.agent` / `record.hostSessionId` name that session.
   - Top-level `createdAt` is the evidence time, equal to `record.createdAt`. `record.sessionCreatedAt` keeps the record file's first appearance.
   - Storage is unchanged: a deliver still lands in the worktree's one manual record. Splitting it per Agent session would move waivers, the stamp the next Stop reads, and verify's write-back onto new keys, for output that a field mapping already fixes. So top-level `session` (= `stamp.session`) stays that record's token; the text calls it "this worktree's deliver record".
   - Attribution is still not hook proof: `hookActive` / `hookActiveSource` are unchanged. Before this turn's Stop, the lifecycle line says that the Stop ending the turn judges the stamp and, if it accepts it, gives the proof.
   - The 0.8.1 ADR kept `agent: manual` "because consumers read it". Every report this round read it as "who delivered" and found it wrong, so the documented meaning ("describes the latest evidence") now gets the value readers expect. The compatibility note is below.
2. **Hook files name both writers.** The runner header reads "Written by harness-kit install-hooks; upgrade refreshes it in place. Do not edit: doctor expects these exact bytes." The working agreement reads "`.agents/hooks/` is written by `install-hooks` and refreshed by `upgrade`". doctor's outdated-runner issue says "upgrade refreshes it in place (or re-run install-hooks)". The routing rule that still sent hooks to install-hooks now says only installing / removing hooks and the linked-worktree Codex dispatcher stay there.
3. **The adoption log is history from its `## Log` heading on.** 5b scans `.agents/adoption.md` only above the first `## Log` heading. Everything from that heading on is history: the Log and the preservation-ledger / blind-audit sections repositories append after it. The preamble is guidance and is still checked. In the downstream history (each adoption.md as it was before the 0.8.1 upgrade), 0.8.1 reported 9 Log lines in 8 repositories that 0.8.2 skips. The preamble pins (line 4, 9 repositories) remain WARNs.
4. **The Stop fallback reads the hook input once.**
   - The Claude / Codex Stop command is now `INPUT="$(cat)"; printf '%s' "$INPUT" | runner || { printf '%s' "$INPUT" | grep -Eq '"stop_hook_active"…true' && <notice>; } || printf <block>`. The guard reads its own copy of the input, so it works however the runner failed: missing file, `git rev-parse` failing, a crash or signal after the runner read stdin, or a hand-edited runner.
   - Reachable paths of H86 before this change: the managed runner exits 0 on every Stop path (`infrastructure_failure` included), so only a runner killed by a signal other than the client's own timeout kill (OOM, a manual kill), or a replaced or edited runner, got there. That is rare but real. The fix costs nothing extra, because H85 changes this command anyway and upgrade rewrites it in the same refresh.
   - The block reason adds the runner's own wording ("If it cannot run here, stop again and say the change is not verified; this blocks a turn only once."). The re-run it lets through prints a notice: Claude Code gets `{"systemMessage": …}` and Codex gets stderr, the same split as the runner's `allowUnverified`. Cursor keeps `runner || printf followup_message` because `loop_limit` already bounds it.
   - Recognition: the 0.8.1 `runner || grep || printf` and 0.8.0 / 0.7.1 commands stay managed and are replaced in place. A local `HARNESS_KIT_CMD=…` override in the buffered command must sit right before `bash`: put up front, it would be a plain shell assignment that never reaches the runner (or `env` would swallow the `INPUT=` assignment). So up front it is not recognized as the Harness command. Overrides on older commands and on SessionStart still go up front.
   - Unchanged: the linked-worktree Codex dispatcher (user directory) still fails closed on a registration mismatch. That was decided when it shipped, and nobody reported it.

## Verification on a real repository copy

A scripted run on a local clone of repo-AM (0.8.1):

- SessionStart went through the installed 0.8.1 client command and runner (real npx @0.8.1).
- `upgrade --check` exited 2 and listed AGENTS.md, the runner, `.claude/settings.json`, and the lock (`hooks.status: refreshed`). `upgrade` then rewrote them in one transaction.
- A same-session deliver was ACCEPTED. evidence showed `agent: claude`, `record.kind: agent-deliver`, `hostSessionId: e2e-081-session`, `createdAt` equal to the evidence time, and `lifecycle.stop: null` with the explanation.
- The Stop through the new client command: `rebound: true`, `hookActive: true`, doctor ACTIVE.
- Runner file missing: the first Stop blocked with the new reason; the re-run was allowed with the systemMessage.
- A runner that reads stdin and exits 1 (a crash, or an edited runner): the 0.8.1 command blocked both times, the 0.8.2 command blocked once and then allowed with the notice.

## Compatibility and upgrade

- **Contracts.** No CLI flag or help text changed, and the manifest schema is unchanged.
- **evidence JSON** (not a declared contract, but scripts read it):
  - Top-level `agent` is now the Agent name, not `manual`, for a deliver an Agent ran from its shell. `record.kind` has a new value `agent-deliver`.
  - Top-level `createdAt` is now the evidence time.
  - A script that needs "was this a deliver command?" should test `record.kind !== "lifecycle"`. Hook proof is `hookActive`, as before.
- **Generated bytes.** The runner, Claude / Codex Stop commands, and AGENTS.md (working agreement sentence) change, so `upgrade --check` reports them.
- **Version.** Fixes with no CLI or schema change: 0.8.2 (patch).
- **Upgrading a repository on 0.8.1:**
  1. `npx -y @erzhe/harness-kit@0.8.2 upgrade --repo . --check` (exit 2 = available), then `upgrade --repo .` on a clean tree. It rewrites AGENTS.md, the hook runner, the client configs, and the lock.
  2. In the same session, `deliver` and finish the turn. The Stop rebinds the session, as in 0.8.1.
  3. Commit.
  4. Only for linked-worktree Codex: run the `install-hooks … --allow-user-dispatcher` command upgrade prints.
  5. A hand-added `HARNESS_KIT_CMD` prefix in a Stop command is dropped by the refresh, as every reinstall does. Put it back right before `bash`.
- **Not upgrading** keeps 0.8.1's behavior, with no gate or security impact. evidence keeps the misleading top-level fields. doctor keeps flagging Log lines (advisory WARN). The fallback stays silent on the re-run, and it loops only when a runner dies after reading stdin. Upgrade at the next maintenance task; nothing needs an immediate rollout.
